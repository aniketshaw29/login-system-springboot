# 06 — Testing the API (Step by Step)

## Prerequisites

Start the application:
```bash
mvn spring-boot:run
```

You should see in the console:
```
Tomcat started on port(s): 8080 (http)
Started LoginSystemApplication in X.XXX seconds
```

---

## Test with curl (command line)

### Step 1: Verify app is running
```bash
curl http://localhost:8080/api/ping
```
Expected: `{"status":"ok","message":"Login System is running!"}`

---

### Step 2: Register a user
```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "alice",
    "email": "alice@example.com",
    "password": "mySecret123"
  }'
```

Expected response (201 Created):
```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhbGljZSIsInJvbGVzIjpbIlJPTEVfVVNFUiJdLCJpYXQiOjE3MzA....",
  "tokenType": "Bearer",
  "username": "alice",
  "email": "alice@example.com",
  "roles": ["ROLE_USER"]
}
```

**Save the token!** You'll need it for the next steps.

---

### Step 3: Try registering with same username (should fail)
```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "alice",
    "email": "other@example.com",
    "password": "password123"
  }'
```

Expected response (409 Conflict):
```json
{
  "success": false,
  "message": "Username 'alice' is already taken"
}
```

---

### Step 4: Try registering with invalid data (validation)
```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "ab",
    "email": "not-an-email",
    "password": "short"
  }'
```

Expected response (400 Bad Request):
```json
{
  "success": false,
  "message": "Validation failed: username: Username must be 3-50 characters; email: Please provide a valid email address; password: Password must be at least 8 characters"
}
```

---

### Step 5: Login
```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "alice",
    "password": "mySecret123"
  }'
```

Save the token from the response.

---

### Step 6: Access protected endpoint WITH token
```bash
# Replace TOKEN with the actual token from step 5
TOKEN="eyJhbGciOiJIUzI1NiJ9..."

curl http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer $TOKEN"
```

Expected:
```json
{
  "id": 1,
  "username": "alice",
  "email": "alice@example.com",
  "roles": ["ROLE_USER"],
  "active": true,
  "createdAt": "2026-01-01T12:00:00"
}
```

---

### Step 7: Access protected endpoint WITHOUT token
```bash
curl http://localhost:8080/api/auth/me
```

Expected (401 Unauthorized):
```json
{
  "success": false,
  "message": "Unauthorized"
}
```

---

### Step 8: Try admin endpoint as regular user
```bash
curl http://localhost:8080/api/admin/users \
  -H "Authorization: Bearer $TOKEN"
```

Expected (403 Forbidden):
```json
{
  "success": false,
  "message": "Access denied: you don't have permission for this resource"
}
```

## Test with H2 Console

1. Open `http://localhost:8080/h2-console`
2. JDBC URL: `jdbc:h2:mem:logindb`
3. Username: `sa`, Password: *(empty)*
4. Click **Connect**

Run these SQL queries to see what's stored:

```sql
-- See all users (password is a hash, not plain text!)
SELECT id, username, email, password, active, created_at FROM users;

-- See the roles table
SELECT * FROM user_roles;

-- Join them together
SELECT u.username, u.email, ur.role
FROM users u
JOIN user_roles ur ON u.id = ur.user_id;
```

Notice: the password column shows a BCrypt hash like `$2a$10$...`, never the real password.

## What to Observe in the Console

When running `mvn spring-boot:run`, watch the logs.

**On a valid request**, you'll see Hibernate SQL:
```sql
select u1_0.id, u1_0.active, u1_0.created_at, u1_0.email, u1_0.password, u1_0.updated_at, u1_0.username
from users u1_0
where u1_0.username=?
```

**On startup**, you'll see Hibernate creating tables:
```sql
create table users (
    id bigint generated by default as identity,
    active boolean not null,
    ...
)
```

This is `spring.jpa.show-sql=true` in action — you can see exactly what SQL
Hibernate generates for your JPA operations.
